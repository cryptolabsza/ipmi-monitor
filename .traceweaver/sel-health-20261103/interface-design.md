# SEL/time concrete implementation design

Status: proposed implementation detail within the owner-approved plan. Root must accept precode preparation before production mutation. No installed firmware is qualified by this document.

## API and request intent

Existing `POST /api/server/<bmc_ip>/clear_sel` and `POST /api/clear_all_sel` remain compatible route locations, but require current admin + session-bound `X-CSRF-Token`, exact trusted request origin, JSON and identity/policy revision. Bodyless legacy requests fail closed. No clear side effect is introduced on GET. Bulk returns per-target guarded operation outcomes; HTTP success never equates to hardware completion.

`GET /api/server/<bmc_ip>/sel/health` is view-authorized and inventory-scoped. It reads persisted evidence only and returns `{bmc_ip, server_name, target_id, identity_revision, health, policies, capabilities, operation}`. `health` includes fixed `state` enum (healthy/nearly_full/full/logging_disabled/clock_incorrect/unknown), independent flags, `logging_enabled: bool|null`, `percent_used: number|null`, native clock/time quality and independent observed/fresh timestamps. Combined conditions remain visible even when one headline has priority. Unobserved/stale data is unknown; capabilities explain unavailable controls. `policies` has separate `automatic_clear` and `automatic_clock` booleans, revision, consent identity and settings. View cannot start network/device work. Admin response additionally carries a session-produced `csrf_token`; read roles never receive mutation authority.

`POST /api/server/<bmc_ip>/sel/policy` accepts only named booleans/settings, `target_id`, `identity_revision`, `policy_revision`, not host/credential/command/qualification data. It atomically compares revision and binding, bumps revision and independently records each consent change. Defaults off on create/migration. Revoke invalidates queued dispatch. Settings: near-full default90%, clock drift default300 seconds; input bounds documented by implementation.

`POST /api/server/<bmc_ip>/sel/enable` and `/sel/clock` use the same guard, current identity and operation boundary. `GET /api/server/<bmc_ip>/sel/operations/<operation_id>` reports only authorized target outcomes. Missing/retired/disabled/ambiguous targets reject before credential lookup or network. Known target without a valid request intent returns403; fully valid request for unknown target404; unsupported/unqualified action409 with safe code/explanation. Running operation returns202 with operation ID, never false success. Responses/errors exclude raw command arguments, secrets and exception bodies.

Direct mode origin derives from trusted request scheme/host. Fleet mode uses the existing positively authenticated trusted proxy boundary; arbitrary forwarded host/proto/base-path headers cannot select origin. Session intent binds subject/auth mode, rotates on subject/session change and does not accept another user's token. Request size and allowlisted field/type bounds apply. Proxy/base-path verification is a required test, not inferred from local direct-origin success.

## Durable data contract

Use existing SQLAlchemy/SQLite migration mechanism. New `SELTarget` has opaque UUID primary key, configured server row ID, exact log selector (`ipmi:sel`), stable hardware fingerprint, binding revision, generation, snapshot epoch, active operation ID and persisted independent health evidence. Server numeric ID or BMC IP alone is not physical identity: qualify hardware GUID/manufacturer/product/firmware and explicit inventory source/revision if present. Missing/changed identity revokes policy and invalidates snapshots; no automatic rebinding of consent.

`SELPolicy` is unique per target and stores independent default-false clear/clock switches, target fingerprint, binding revision, revision, admin subject/consent timestamp and thresholds. `SELOperation` stores UUID, target/binding/policy revision, action, initiator/reason, state, attempts/deadline/cooldown, receipt/digest, before/after evidence, safe outcome code and timestamps. State enum: queued, archiving, mutating, verifying, complete, failed, outcome-unknown. Unique target ownership is claimed by atomic conditional DB update (`active_operation_id IS NULL`) in a committed transaction, not a process-local mutex. Expired process ownership is not permission to replay a mutation: startup/worker reconciliation inspects durable state. Clear and clock use the same owner. Never release ambiguous operation into an immediately writable target; a recorded reconciled disposition is required.

`SELArchive` stores complete ordered raw records (bytes as hex/base64, including undecodable records), collection identity/generation/epoch, reservation bytes, bounded traversal details, first/last/count/completeness, trusted `collected_at`/`archived_at`, SHA256 and immutable receipt UUID. Archive + operation intent + independent `SELAudit` commit atomically before any clear. Do not swallow commit/audit errors. Verify SQLite durability settings used by the store; use committed database blobs/transactions rather than an uncommitted temporary file as a receipt. Quota/size/timeout limits fail closed. Pending/reconciling receipt cannot be deleted; configured existing retention starts at trusted archive time. No separate purge/entitlement duration is introduced.

`IPMIEvent` gains target/generation/raw digest/native timestamp text/time-quality metadata. Deduplication keys are stable identity + reconciled generation + SEL record ID + raw digest; timestamps are not identity. Generation advances on observed clear/reset/record-chain changes and guarded clear, without fabricating exact legacy history. Inconsistent chain/raw changes retain evidence and flag reconciliation instead of overwriting. Legacy migration assigns preserved rows explicit legacy/unknown quality and unique preserved IDs, not fabricated native precision. SQLite table rebuild may be needed to replace `unique_event(bmc_ip,sel_id)`; copy every legacy column/row/index transactionally, verify counts and rollback failure, then atomically swap. All collectors, refresh/recollect paths, Redfish and admin-audit insertions must be enumerated before GREEN. Current parser→save test uses actual producer objects to guard reused IDs. Independent audit records survive ordinary SEL/history deletion.

Retention uses trusted collected/archive time and the unchanged configured duration. Existing retention fixtures that mark records expired only via BMC `event_date` must explicitly set old `collected_at` too, preserving their batching/concurrency assertions under the new trusted-time contract; this is a fixture correction, not a weakened gate. Explicit database-history delete may delete ordinary eligible history but must preserve active operation backups and action/consent audit.

## Qualified adapter and dispatch

New focused `src/ipmi_monitor/sel_management.py` registers models/services against the existing runtime and contains a fixed IPMI raw-command adapter. No new dependency. Secret goes through an invocation-local environment `IPMI_PASSWORD` with `-E`, never argv `-P` or a fallback. Use complete target username/secret and a fixed authenticated lanplus/cipher profile. No user-supplied raw commands; sanitized failures. Qualification must verify target authentication properties; default `lanplus` alone is not a qualification claim.

Reads use fixed Get Device ID/GUID, Get SEL Info, current global logging control, Get SEL Time and supported UTC Offset operations. A raw reservation ID is obtained before the final snapshot; every Get SEL Entry traversal carries that reservation and bounded next-record chain detection. Preserve every raw byte even if decode fails. The same reservation goes into Clear SEL initiation; never call `ipmitool sel clear`. A reservation-invalid response abandons the receipt for deletion authority and permits at most two bounded read/archive attempts, never unguarded clear. Do not stop logging. Clear completion status/readback is bounded; nonempty post-clear log may contain new records and is not grounds to re-clear. Transport timeout after dispatch is outcome-unknown and cannot trigger blind retry. Do not infer firmware invalidates reservation on insertion: qualification must demonstrate it; otherwise clear unavailable.

Clock reference must be verified synchronized UTC with a fresh proof (e.g. bounded chrony/timedatectl read on supported deployed Linux) and independent age/duration checks. Mac local test time is not runtime trusted reference. Unsupported/unavailable sync proof yields warning only. Healthy external NTP is respected; unhealthy externally managed time is warning only. Standard IPMI cannot universally reveal NTP ownership: an exact qualified current-status probe must establish it, or writes stay unavailable. No NTP reconfiguration. Offset-capable hardware captures native offset, computes qualified native SEL time, writes time, restores offset reset by Set SEL Time, and verifies clock + offset. Undefined offset/time mapping or unsupported current-management evidence prevents writes. Failure after time write is outcome-unknown/incomplete, no second blind write sequence. Proposed readback tolerance5 seconds, trusted reference age30 seconds, observation freshness max(120 seconds, twice configured poll period), action timeout60 seconds, maximum two read attempts and300-second per-target mutation cooldown are bounded implementation settings, not new hardware claims; document values at GREEN and qualify them per device. Clock dispatch invalidates snapshot epoch before any later clear can proceed.

## Exact qualification evidence contract (default empty)

Use a server-owned, read-only qualification registry consumed at startup, outside API policy fields; there is no UI/API global bypass or “qualified=true” endpoint. A qualification entry requires schema `sel-device-qualification/1`, record UUID/digest, independent reviewer identity and approval timestamp, evidence file digests, supported adapter/tool version + exact device manufacturer/product/firmware/GUID fingerprint and log selector, fixed transport/security profile and separately approved actions. Missing/mismatched records disable that action.

Per-action evidence must include exact target canary operation IDs/raw receipts, observed current state and capability probes, times, outcome, and expiry/requalification rules. Clear requires a demonstrated same-reservation full-read/committed-backup/conditional-clear guard, insertion and competing-reservation invalidation proof, empty/failure distinction, bounded completion/readback and arrival-after-clear preservation. Enable requires unrelated-bit preservation and enabled readback. Clock requires positive/negative offset/native mapping, offset restoration, trusted fresh reference, current external-management probe, healthy-NTP preservation, interrupted time/offset write behavior and readback tolerance. Reviewer must accept evidence for the exact supported device/firmware/transport, not only generic vendor family. Replacement/firmware/adapter/security-profile changes revoke the qualification match and automation consent. Local synthetic records/tests are marked test-only and cannot enter runtime registry. Initial shipped registry is empty; useful health/warnings ship with unavailable writes until actual authorized qualification. No actual target canary is authorized in this task.
