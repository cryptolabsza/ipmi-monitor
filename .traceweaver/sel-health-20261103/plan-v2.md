# IPMI BMC log health and native clock — revised plan v2

Status: candidate revised plan for security review and owner approval. Source snapshot: c0a3b83724d993ef2f806a4a12305025d72c2b88, local origin/dev; remote freshness unverified. No source code, live BMC, release or deployment work performed.

## User scope
- Detect full BMC SEL logs and machines whose Event Logging is currently disabled; warn by machine name and BMC IP.
- Give authorized users the ability to enable Event Logging and automatic clearing.
- Include correction of the BMC's native date/time (interpreting 'native clock' as BMC/SEL clock).
- Owner explicitly selected: 'Clear the BMC copy after verified backup; keep saved history under existing retention (Recommended)'. Saved backups are not deleted as a side effect of BMC clearing.

## 1. Supported identity and current status
Implement IPMI as the first qualified mutation transport; existing Redfish read support remains, but no generic first-LOG-match mutation or unqualified Redfish auto-clear. State, entries and each action must refer to the same configured active server identity and exact SEL. Unknown/ambiguous/unsupported devices display warnings with unavailable actions.
Persist capacity, logging state, native clock, observation time, protocol/capability and freshness independently. Read current logging control instead of inferring it from old events. Missing or expired evidence is Unknown/Stale, never healthy/full. Proposed near-full warning threshold is 90% when capacity is reliably measurable; full status also uses authoritative device evidence. Auto-clear trigger is confirmed full, not merely near-full. Missing capacity disables percentage-based triggers.

## 2. Intentional, scoped operator controls
Dashboard and server page show Full, Nearly Full, Logging Disabled, Clock Incorrect, Unknown/Stale and operation outcomes per machine. New controls are Enable Event Logging, Sync BMC Clock Now, Clear Backed-up BMC SEL, Automatic Clearing and Automatic Clock Correction. The two automatic policies are separate per-machine opt-ins, default off on installation and migration.
Use admin-only mutation and policy consent for this increment. Read roles retain existing permitted viewing. Every mutation requires server-side role and session-bound request-intent/CSRF checks, with exact-origin validation compatible with direct and supported Fleet proxy/base-path modes. No state-changing GET routes. Fix existing shared SEL rendering sinks in both shipped template trees to render BMC text, names and errors as text, not executable HTML; warning/control classes come from fixed enums.
Resolve configured, enabled, authorized stable server/log identity before credential lookup or network access. Bind consent to that identity and a revision; replacement/rebinding/uncertain identity disables automation pending renewed consent. Recheck current revision/lifecycle immediately before dispatch. Revocation stops queued work; an already accepted hardware action cannot be recalled and is reported truthfully.

## 3. One backup-before-clear workflow
Manual, bulk and automatic BMC clears share the same guarded workflow. Remove local-history deletion from every BMC-clear path. A database-enforced per-server/log operation owner serializes clear and clock operations across request/collection workers.
Before clearing, obtain a hardware conditional-delete token/reservation that covers the final complete read and the clear. Traverse all pages/records with bounded time/size, preserving undecodable raw records. Return explicit success/completeness, target identity and record evidence. Commit the complete backup plus operation/audit intent and durable receipt before dispatch. Empty success differs from read failure. Partial reads, malformed data without raw preservation, missing pages, failed commits, storage/quota failures, expired evidence or audit failure cause no clear.
The mutation adapter must clear using the SAME reservation used for the final archived snapshot; do not invoke a standalone clear utility that obtains a fresh one. A new event or competing requester that invalidates the reservation causes bounded re-collection, never unguarded deletion. Do not disable logging to create a quiet window. If a device/transport cannot demonstrate an equivalent hardware guard, automatic AND history-preserving manual clear are unavailable, with a visible explanation. A lossy override is outside this plan.
Existing saved-history access and retention period remain. Measure archive eligibility from trusted archived_at, retaining original BMC dates as evidence, so a bad BMC clock cannot immediately expire a new backup. Protect the referenced backup while an operation is pending/reconciling and for the configured existing retention window after archive. Do not silently expand entitlement duration or add a separate backup purge policy. Action/consent audit is kept outside ordinary SEL clearing. Explicit existing database-history deletion must not erase audit or a backup required by an active operation.

## 4. Durable operation state and event identity
Persist operation states (queued, archiving, mutating, verifying, complete, failed, outcome-unknown), target identity, policy revision, archive receipt, initiator, reason and observed outcome. After timeout/crash/restart, reconcile existing intent/device state before any new mutation; never blindly retry or promise exactly-once hardware effects. Poll supported clear/task status with bounded deadlines. A successful command exit/HTTP 202 is not completion; a nonempty log can contain new events which must survive verification. Apply bounded attempts, per-machine cooldown and visible holds for ambiguity/repeated failure.
Migrate event identity from (BMC IP, SEL ID) to stable server/log identity plus reconciled generation and raw record evidence, updating all insertion/deduplication paths. Handle device reset, external clear, record-ID reuse and server replacement without overwriting or suppressing events. Timestamps alone cannot identify a record. Preserve existing records with a compatible migration and database constraints.

## 5. Correct the BMC native clock safely
Detect impossible/uninitialized dates and drift against a verified trusted UTC reference. Proposed drift threshold: five minutes, configurable; no automatic writes on missing/ambiguous clock or timezone data. Account for vendor clock and offset semantics explicitly; do not interpret local time twice or assume SEL time equals every other BMC clock.
Prefer an already configured, healthy BMC NTP/time service as authority. Report unhealthy externally managed time rather than fighting it or changing NTP servers. Otherwise allow admin-approved automatic correction only for qualified writable hardware and a verified fresh reference (monitor clock synchronization must be proved if used). No changes to the server OS clock, this Mac, or GPU frequency. Unsupported/ambiguous hardware remains warning-only.
Preserve raw native event timestamps, native time before/after, desired UTC, trusted observation/collection time and time-quality flags. Do not backdate/rewrite history or substitute collection time as if it were a measured event time. Audit correction independently; protect records with uncertain BMC dates from premature retention cleanup. Verify clock readback within a documented tolerance before reporting success. Serialize with archive/clear; a clock write must invalidate stale clear snapshot evidence and cannot manufacture archive completeness. Use bounded retries/cooldown and reconcile ambiguous results before any further writes.

## 6. Credentials and target transport
Use the existing approved credential source and complete per-server username/secret. The scoped SEL/time adapter must use a non-argv secret channel, never -P fallback, sanitized exceptions and logs; do not refactor unrelated credential storage. Use only fixed allowlisted commands/actions and configured targets. Qualified IPMI transport must authenticate the intended BMC without weakening cipher/security settings. Any future Redfish mutations require verified CA/pin trust, exact-origin paths and no credential-bearing redirects; they remain disabled in this increment.
