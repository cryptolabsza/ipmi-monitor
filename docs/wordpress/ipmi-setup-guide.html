📦 Requirements

Host System

  • Linux (Ubuntu 20.04+, Debian, CentOS)
  • Python 3.9+ (for pipx install)
  • OR Docker & Docker Compose
  • Network access to IPMI/BMC interfaces

Your Servers

  • IPMI/BMC interface enabled
  • BMC IP accessible from host
  • IPMI credentials (username/password)
  • SSH access (optional, for enhanced monitoring)

💡 Understanding Server IP vs BMC IP

Your server has two different IP addresses that serve different purposes:

🖥️ Server/SSH IP

The main OS IP address (e.g., 192.168.1.100)
Used for: SSH, applications, normal access
Enter this in the SSH Host field

🔧 BMC/IPMI IP

Separate management interface (e.g., 192.168.1.101)
Used for: Out-of-band management, power control
Enter this in the BMC IP field

Then run docker compose -f /path/to/your/docker-compose.yml pull ipmi-monitor followed by docker compose -f /path/to/your/docker-compose.yml up -d ipmi-monitor. ⭐ Option 1: pipx install RECOMMENDED

Install the setup CLI from the released GitHub main branch and select the main Docker image. Verified on 7 November 2026: main is IPMI Monitor 1.4.2 (commit de79838). The CLI and running Docker container are separate artifacts; updating the CLI alone does not update the dashboard.

Step 1: Install & Run Setup

sudo apt install pipx git -y
pipx ensurepath
pipx install --force git+https://github.com/cryptolabsza/ipmi-monitor.git@main
pipx inject --force ipmi-monitor git+https://github.com/cryptolabsza/cryptolabs-proxy.git@main
# New install: explicitly use the released main image
printf 'ipmi_monitor:\n image_tag: main\nssl:\n mode: self_signed\n' > ipmi-config.yaml
sudo "$HOME/.local/bin/ipmi-monitor" setup -c ipmi-config.yaml

The wizard will guide you through adding your first server. This config explicitly enables the CryptoLabs Proxy with self-signed HTTPS; use the dashboard URL printed by setup. For a public certificate, configure ssl.mode: letsencrypt with your domain and email.

Step 2: Add More Servers

ipmi-monitor add-server --bmc-ip 192.168.1.10 --username admin --name server-01

Step 3: Open Dashboard

Use the HTTPS dashboard URL printed by setup

🔐 Set Up SSL & Branded Dashboard

Set up HTTPS access with a beautiful landing page that links to all your monitoring services.

Self-Signed Certificate (Quick Setup)

# Basic setup (IP access only)
sudo ipmi-monitor setup-ssl

# With custom site name
sudo ipmi-monitor setup-ssl --site-name "My Server Fleet"

# Include DC Overview if installed
sudo ipmi-monitor setup-ssl --dc-overview --vastai

Let’s Encrypt Certificate (Production)

sudo ipmi-monitor setup-ssl 
  --domain ipmi.example.com 
  --letsencrypt 
  --email admin@example.com 
  --dc-overview --vastai

🌐 DNS Setup (for domain)

Add these DNS records pointing to your server IP:

A ipmi.example.com → <server-ip> Main dashboard
A grafana.ipmi.example.com → <server-ip> If using DC Overview

🐳 Option 2: Docker Compose

docker-compose.yml

version: '3.8'

services:
  ipmi-monitor:
    image: ghcr.io/cryptolabsza/ipmi-monitor:main
    container_name: ipmi-monitor
    restart: unless-stopped
    ports:
      - "5000:5000"
    environment:
      - APP_NAME=My Server Fleet        # Customize this
      - IPMI_USER=admin
      - IPMI_PASS=YourIPMIPassword      # Your BMC password
      - ADMIN_PASS=changeme             # CHANGE THIS!
      - SECRET_KEY=change-this-to-random-string
    volumes:
      - ipmi_data:/app/data             # ⚠️ Persists your data!
      - ./keys:/app/keys:ro             # SSH keys (optional)

volumes:
  ipmi_data:

Start the service

docker compose up -d

⚠️ Important: Data Persistence (Docker)

Always use a named volume to preserve your data across container updates:

✅ CORRECT – Named volume

volumes:
  - ipmi_data:/app/data

❌ WRONG – No volume

# (no volume specified)
# Data lost on rebuild!

🔧 Troubleshooting

Can’t connect to IPMI/BMC?

Make sure the BMC IP is reachable from your host:

ping <BMC_IP>
ipmitool -I lanplus -H <BMC_IP> -U admin -P password chassis status

SSH connection fails?

Check that:
• SSH Host is the server OS IP, not the BMC IP
• SSH key has correct permissions (600)
• For Docker: keys are mounted correctly
