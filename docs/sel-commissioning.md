# SEL commissioning and qualification

The monitor distinguishes `manual_commissioning` from `automatic_qualified` in v2 action admissions. The health API exposes the phase and automatic availability. A manual commissioning record permits one exact target/action attempt through the ordinary authenticated admin POST with the existing session intent, origin, identity, revision and credential checks. It cannot arm an automatic policy. Its UUID is consumed atomically when the durable operation is claimed, including when backup later fails. Replacing a bundle does not refund that UUID. Operation and audit receipts survive ordinary event/archive retention.

A commissioning record is qualified authority before the first write. The reviewer must establish exact full fingerprint/GUID and firmware/transport applicability, conditional erase and insertion/competing-reservation semantics from retained vendor evidence and genuine native guard observations. Software tests establish application safeguards. Separate `owner_scope` evidence records the exact target ID/full fingerprint/action/commission UUID, `max_attempts=1`, approval/expiry and retained owner instruction. Owner consent is not firmware evidence. Current manual pilot scope is a separately root-approved CCC93 clear only; this document grants no live action. CCC94 remains excluded. Clock qualification remains separately held wherever offset, mapping, trust, UTC reference or complete external-writer ownership is unknown.

The registry schema is `sel-device-qualification/2`. Common record fields retain the v1 exact identity/runtime/reviewer/expiry controls. Actions use `phase`, `commission_id`, `owner_scope_sha256`, and a closed claim-to-evidence-digest map. Evidence artifacts specify `path`, `sha256`, and `kind`. Typed JSON uses `sel-typed-evidence/2`, binding record ID, full fingerprint, runtime identity, action, kind and explicit provenance. The common runtime identity binds the final admission. A native observation retains its actual observation-time installed runtime, probe source/tool identity and limitations separately in its evidence/provenance; an older observation is never relabeled as final-source verification. The kinds are `owner_scope`, `vendor_semantics`, `native_guard_observation`, `source_guard_verification`, `clock_ownership`, `commissioning_result`, and the existing parsed `ca_certificate`. Every required claim admits only its designated kinds; missing, ambiguous, duplicate or misclassified evidence refuses the entire bundle. Schema validity is not independent semantic review. The v1 validator and its complete-canary evidence requirements remain unchanged.

Before either clear or clock, the monitor takes a complete raw snapshot and commits it to `SELArchive`, writes a private UUID-named file under explicit `DATA_DIR/sel-archives`, fsyncs the file and directory, and independently reads both back. Payloads bind operation/target/full fingerprint, generation/epoch, reservation, collection UTC and qualification. At final dispatch the monitor reloads the database and file and verifies exact bytes and original digest/bindings under the existing authority fence. Any failure holds the write. Clear retains the same reservation/session through the final snapshot and erase; reservation loss never authorizes a fresh-token erase. Clock preserves a valid empty snapshot too, then reaps its read-only snapshot shell before the existing guarded direct clock path. The reservation does not make clock writes conditional. Existing offset restoration/readback, trusted reference, CA validation and external-management controls remain.

Database and file are two durable verified representations on one volume. They are not independent disaster-recovery failure domains. Existing retention timing and entitlement continue. Eligible archive files and rows are removed together; active/unknown operations protect their archives. Saved event history is not deleted by a BMC clear. A failed or ambiguous accepted effect remains owned and must be reconciled without blind replay.

For promotion, supply `parent_commission` with the prior envelope/pointer hashes, same commission UUID, exact successful operation ID and admitted result hash. The loader cross-checks the real local manual operation, original qualification binding, target/action/fingerprint/runtime, immutable archive pair, dispatch and completion audits, raw mutation/completion/readback receipts, preserved-history counts and an ordinary post-operation collection receipt. A syntactically valid result JSON cannot promote a missing, failed, foreign or unknown operation. New events after a clear are valid. Retained source evidence is never physical evidence. The retired manual record and owner scope are checked at the actual durable claim time; the current automatic record and owner scope expire against current UTC. First or changed promotion requires the actual raw DB/file proof still present. Under the existing authority fence the installer writes and verifies a private, checksummed acceptance receipt in the existing transition history, bound to the exact candidate pointer/envelope/registry, record/admission, runtime/GUID, consumed operation and immutable audit hashes. Subsequent lookups verify that receipt and retained local facts, allowing raw archives to expire normally. A dormant receipt cannot authorize another active pointer. Altered/missing acceptance or local facts hold eligibility; source tests cannot create physical truth. Exact unchanged accepted records may carry into a new explicitly replaced pointer using a new receipt and verified retained facts; changed admission cannot borrow that authority. Environment-mode automatic v2 records and automatic initial installs are refused.

Initial managed installation is unchanged. Supported replacement is explicit:

```sh
python -I -m ipmi_monitor.sel_qualifications replace \
  --expected-active-pointer-sha256 <exact-current-pointer-sha256> \
  --expected-sha256 <candidate-envelope-sha256> < candidate-envelope.json
```

Run the existing offline operator boundary as root with explicit protected `DATA_DIR`. Environment qualification overrides refuse managed install/replace. Replacement revalidates old and candidate bundles/runtime, requires every automatic policy off and no unresolved operation, then checks the exact active pointer under the SQLite authority transaction. It retains old/new immutable bundles, pointer bytes and transition intent/result before/after atomic publication. An uncertain publication returns `outcome_unknown`; inspect supported `status` and retained receipts before any further transition. Historical bundle reactivation is refused; rollback is a new reviewed transition, not copying an old pointer file. Fresh authenticated policy consent is required after a verified replacement. No replacement command grants live commissioning or automatic consent by itself.

The retained synthetic Linux round-trip lane is `python -m tests.test_sel_activation --linux-promotion` in an isolated root Linux test image with the existing development pytest dependency. It reuses the real application/adapter/collector fixtures and managed file/SQLite construction; only external tool/TLS boundaries are synthetic. Run the offline custody/CAS lane separately with `python -I tests/sel_qualification_linux.py`. These lanes establish application integration, not firmware conformance or target acceptance.

The clock integration variant is `python -m tests.test_sel_activation --linux-clock-promotion`. It uses the same actual managed operation/collection/promotion/retention/carry-forward lane and verifies the selected managed CA bytes and credentials at the existing synthetic TLS boundary. Historical runtime binding reconstruction resolves CA trust paths against the exact original parent bundle, matching commissioning selection; structural acceptance hashing continues to use raw bundle records. The current bundle's path cannot substitute for the original parent's path.
